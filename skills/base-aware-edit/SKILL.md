# base-aware-edit — 変える行の出自で慎重さを切り替える

## なぜ

ユーザーは PR の中で設計やコードを何度も書き直す。この PR で足したものは誰も依存していないので書き直してよい。
ただし、その勢いでベースブランチに既にあるコードまで書き換えると、動いているものを壊す。ここを止めるのがこの skill の目的。

## 判定

1. ベースを決める: PR があれば `gh pr view --json baseRefName -q .baseRefName`、なければ `main`（無ければ `master`）。`base=$(git merge-base origin/<ベース> HEAD)`
2. 編集したい行が `base` に存在したかを見る
   - `git diff $base -- <file>` で、その行が `+` だけ（追加）ならこの PR の行
   - `git blame $base -L <開始>,<終了> -- <file>` が通り、同じ内容の行が出るならベースの行
   - 迷ったらベース側として扱う

| 行の出自 | 扱い |
|---|---|
| この PR で追加した行（既存ファイルへの新規メソッド丸ごと追加を含む） | ゼロベース。過去コミットの自分の判断に縛られず、消す・作り直す・設計を変えてよい |
| ベースにある行（差分上で変更扱いの行を含む） | 慎重側。下の手順を踏む |
| 名前の変更・整形だけ | 慎重側でも手順は省いてよい。影響範囲（呼び出し元）だけ確認する |

## 慎重側の手順

変更前に次を確かめる。

1. 呼び出し元・参照元を grep し、変更が届く範囲を数える
2. その行がそこにある理由を探す: 周辺のコメント、テスト、名前
3. 理由が読み取れない、または一見不要に見える分岐・順序・値なら `trace-design-origin` skill で入れた PR まで辿る
4. ユーザーに次を示し、了承を得てから変える
   - 変えたい行（`file:line`）と、変えたい理由
   - その行がある理由（見つからなければ「見つからなかった」と書く。推測で埋めない）
   - 影響範囲（呼び出し元の数と主なもの）
   - 変えずに済む代替案があればそれも

了承は示した範囲に限る。別のベース側の行を変えるときは改めて示す。

## しないこと

- この PR の行に、この手順を当てはめて遅くしない
- ベース側の変更を「ついで」に混ぜない。必要なら上の手順で明示してから入れる
