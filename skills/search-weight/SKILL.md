# Search Weight

あなたはケチな検索者です。一番狭い起点、一番少ない出力で探します。
広く投げる前に、専用コマンドで済まないか考えます。

## 重さは時間だけでは測れない

| 要因 | 重い例 |
|---|---|
| 起点の広さ | `/`、`~`、ホーム配下のキャッシュやツールの置き場（`~/Library`、`~/.local`、`~/.cache` など）、複数 repo をまとめた親ディレクトリ |
| 出力量 | error / fail / version などの汎用語。除外なしの `rg --files`。数秒で1億 token 級になる例もある |
| 繰り返し | タイムアウトした直後に、同じ条件で再実行 |
| 索引作成 | 索引の無い場所でコード索引ツールを実行する。GB 単位の索引ができることがある |

## 最初に当てはまった手段を使う

1. 場所が分かっている？ → `ls` か直接 Read
2. 専用コマンドがある？ → gem: `bundle info` / repo: `ghq list -p | rg <名前>` / インストール済みのもの: そのツールの list コマンドか設置ディレクトリ
3. 対象 repo が決まっている？ → その repo の中で `rg` / `fd` / `git grep`
4. シンボルの呼び出し関係？ → 索引がある repo なら索引ツール / ast-grep
5. どれでもない → 範囲をユーザーに聞く。広域検索はしない

## 守ること

- 出力は軽い順に見る：`rg -l` → `rg -c` → `rg -n ... | head -50`
- 汎用語で検索しない。具体的な名前1〜2語で探す
- ヒットが多すぎたら、同じ検索を投げ直さない。語か範囲を狭める
- タイムアウトしたら、同じ条件で再実行しない
- 上の表に挙げた広い起点は使わない。必要なときは理由と範囲を示して聞く
- `--no-ignore` / `--hidden` は付けない。付けるときは理由を言う
- 索引を作るツールを、索引の無い場所で実行しない
- エージェントの会話ログ（例：`~/.claude/projects`、`~/.codex/sessions`）は、ユーザーが求めたときだけ検索する。その場合も対象を絞る（秘匿情報が混ざるため）
- サブエージェントの並列起動は、ユーザーが求めた数まで
